## Commands

Every command here was run against this repository. Nothing is aspirational.

### Lint and format

```bash
bun run lint          # biome check .
bun run lint:fix      # biome check --write .
bun run format        # biome format --write .
```

`bunx ultracite fix [files...]` is equivalent to `lint:fix` and safe to use —
`ultracite doctor` reports `Detected linter: biome`, because `biome.jsonc`
extends `ultracite/biome/core`. Ultracite 7 defaults to oxlint/oxfmt; it drives
Biome here only because of that extends. Do not remove it.

There is no `--write` flag on `ultracite fix` — it writes by definition, and
unknown flags are forwarded to Biome.

### Types, tests, benchmarks

```bash
bun run check-types   # turbo run check-types — tsc --noEmit per package
bun run test          # turbo run test — bun test (unit) + vitest (integration)
bun run test:unit
bun run test:integration
bun run test:coverage
bun run bench         # turbo run bench
```

**`bun bench` is not a command.** Bun has `bun test`, not `bun bench`. Typing
`bun bench` in this repo silently runs the `bench` npm script, which is
`turbo run bench`. The benchmarks are [mitata](https://github.com/evanwashere/mitata)
suites at `<package>/bench/index.ts`, present in `@repo/db`, `@repo/auth` and
`apps/server`, run with `bun run bench/index.ts`.

### Security

```bash
bun run security:check   # bun audit --audit-level=high --ignore <3 GHSAs>
bun run security:audit   # bun audit, unfiltered
bun run security:fix
```

The three ignored advisories are documented with reachability analysis in
`SECURITY-EXCEPTIONS.md`. Never add a fourth without adding its analysis there.

There is no per-package `security:check` task — the audit reads `bun.lock`
once for the whole workspace, so fanning it out would be slower and would
report the same findings N times.

### Database

```bash
bun run db:generate   # drizzle-kit generate  (Postgres migrations)
bun run db:migrate    # drizzle-kit migrate
bun run db:studio
```

**Better Auth's schema is generated by a codemod, not by a migrate command.**
There is no `auth migrate`. Run `bun run auth:generate` from `packages/auth`:
it invokes the Better Auth CLI and then re-applies timezone-aware timestamps,
UUIDv7 defaults, composite indexes and the `account.issuer` column the CLI
omits. **Edit the codemod, never the generated schema files.**

ScyllaDB and Redis have no migration tool. Their schemas are applied by
harnesses:

```bash
cd packages/chat-db && bun run validate:cql   # applies cql/ to a throwaway Scylla
cd packages/kv && bun run kv:up && bun run scripts/validate.ts
```

### Git hooks

```bash
bun run prepare       # lefthook install (runs automatically after bun install)
```

`lefthook.yml` owns them: pre-commit runs Biome on staged files plus
`check-types`; pre-push runs the full test suite and the audit.

## Layout, and one name that differs from the obvious

| Path | What |
| --- | --- |
| `apps/server` | ElysiaJS API + the `/gateway` WebSocket |
| `apps/web` | Next.js 16 |
| `apps/desktop` | Electron (migrated from Tauri) |
| `apps/native` | Expo SDK 57 |
| `packages/db` | Drizzle on Neon Postgres — the relational graph |
| **`packages/chat-db`** | **ScyllaDB.** Not `packages/scylla` |
| `packages/kv` | Redis/Valkey — presence, typing, voice, pub/sub |
| `packages/auth` | Better Auth, Argon2id, username plugin |
| `packages/env` | T3 Env, one entry point per runtime |
| `packages/ui` | Base UI + shadcn-style variants |
| `packages/config` | TypeScript presets only |

Config files are `biome.jsonc` (not `.json`) and `vitest.config.ts` using
`test.projects` — `vitest.workspace.ts` is deprecated in Vitest 3+ and does not
exist here.

## Task protocol

1. **Read the rules first.** They are imported above and they are not generic
   advice — each one records a bug this repository actually hit.
2. **Change code in the package that owns it.** The seams are deliberate:
   Postgres holds the relational graph, ScyllaDB the message streams, Redis the
   ephemeral state. Crossing them is a design decision, not a shortcut.
3. **Self-heal before answering:**
   ```bash
   bun run lint:fix && bun run check-types && bun run test && bun run security:check
   ```
   Fix failures yourself. Do not report a task complete with a red pipeline.
4. **Update this file** when a script, dependency or benchmark changes.

## Reporting

State what was verified and what was not. Most of this repository has never
run — see `SETUP-WINDOWS.md`. A claim that something works, when it has only
been typechecked, is worse than saying nothing: it removes the reason to check.
